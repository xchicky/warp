# M9.2: Environment Context Sub-Spec

## Summary

M9.2 fills the `Dynamic Environment Context` layer introduced by M9.1 with a small, allowlisted, bounded set of runtime facts. The goal is to make the local OpenAI-compatible agent aware of where it is running without leaking secrets, unbounded machine state, or data that belongs in tools.

This milestone is prompt/request assembly only. It does not change plan-mode wording, approved-plan wording, tool schemas, tool policy, shell/file approval behavior, hosted/shared-session prompts, or feature flags.

## Current State

M9.1 now renders the local direct system prompt as six sections in `app/src/ai/agent/local/mod.rs`:

1. `Identity`
2. `Capability Advertisement`
3. `Safety Boundaries`
4. `Tool Catalog`
5. `Dynamic Environment Context`
6. `Current Turn`

The M9.1 environment layer currently contains only the deterministic placeholder `No dynamic environment context is included in M9.1.`

Several environment-like facts already exist elsewhere in the request:

- `AIAgentContext::Directory` carries cwd/home/index status.
- `AIAgentContext::ExecutionEnvironment` carries shell and OS details.
- `AIAgentContext::CurrentTime` carries the current timestamp.
- `AIAgentContext::Git` carries git head/branch facts from the active block.
- `input_context_for_request` in `app/src/ai/blocklist/controller/input_context.rs` already appends current time and active-session execution environment.
- `ActiveSession::is_local()` distinguishes local versus remote/SSH sessions.

M9.2 should fold only the approved facts into the M9.1 environment layer and should avoid duplicating the same facts in older context sections when the environment layer already represents them.

## Goals

1. Replace the M9.1 placeholder with a labeled environment block in normal, plan, and approved-plan implementation requests.
2. Use an explicit allowlist of fields and deterministic rendering order.
3. Keep the static prompt prefix from M9.1 stable; dynamic environment data must stay inside the `Dynamic Environment Context` layer.
4. Keep the environment block under a hard 500-token-equivalent cap.
5. Reuse existing context/session APIs as source of truth. Any new struct or context variant is only a bounded transport/rendering snapshot.
6. Provide installed-app request-body trace evidence before implementation merge.

## Non-Goals

1. Do not add a general environment dump.
2. Do not read or render environment variable values.
3. Do not inspect file contents, shell rc files, network configuration, or full process lists.
4. Do not run new shell commands solely to populate this block unless a reviewer explicitly approves the source and safety boundary.
5. Do not include git commit history, full `git status`, commit SHAs, or changed-file names.
6. Do not introduce a new prompt framework or change hosted/shared-session prompt assembly.
7. Do not move, rewrite, or loosen M8/M9 tool execution policies.

## Environment Field Allowlist

Render these fields when available. Missing optional fields should be omitted unless the absence itself is useful; required-but-unavailable fields may render `unknown`.

Fields must appear in this low-frequency to high-frequency order:

1. `os`
   - Operating system family, for example `macOS`, `Linux`, or `Windows`.
   - Version/distribution may be included only if already available from the existing execution-environment context.

2. `arch`
   - CPU architecture, for example `arm64` or `x86_64`.
   - Prefer Rust/platform constants or existing execution-environment data.

3. `shell`
   - Shell family/name, for example `zsh` or `bash`.
   - Version may be included only if already available from `AIAgentContext::ExecutionEnvironment`.

4. `cwd`
   - Full current working directory path from `AIAgentContext::Directory`.
   - This is useful enough to include even though it can contain a username. It must not expand into directory listings.

5. `git_branch`
   - Current git branch name from existing git context.
   - Do not include commit history or commit SHAs in M9.2.

6. `git_modified_files_count`
   - Integer count only.
   - Do not include file names, paths, diffs, staged/unstaged details, or full status output.
   - If an existing safe source is not available, omit this field or render `unknown`; escalate before adding new git command execution.

7. `process_name`
   - Active foreground process name when already available from session/process helpers.
   - Do not include a full `ps` listing or other users' processes.

8. `session_type`
   - `terminal` for local terminal sessions.
   - `ssh` for remote/SSH sessions.
   - `unknown` only when the session API cannot determine either.

9. `ssh_remote_host`
   - SSH host only for SSH sessions, and only if already available from session metadata.
   - Do not include usernames, IP addresses, DNS configuration, or full SSH command lines unless the existing host field already contains only the safe hostname.

10. `local_writes_disabled`
   - Boolean.
   - Render `true` for SSH/remote sessions where local sync file tools cannot safely write the remote filesystem.
   - Omit for normal local terminal sessions unless implementation needs an explicit `false` for trace/test clarity.

11. `tty`
   - Boolean indicating whether the active session is backed by a TTY when known.

12. `timestamp`
   - ISO 8601 timestamp.
   - Must be the final field in the environment block because it changes most frequently.

## Explicit Deny List

The environment block must not contain:

1. Environment variable values or any full env-var dump.
2. API keys, tokens, provider credentials, cookies, or `.env` contents.
3. File contents.
4. Full git history, commit logs, or commit SHAs.
5. Full process output, full `ps` output, or other users' process lists.
6. Full home-directory contents or filesystem listings.
7. Network configuration such as IP addresses, DNS servers, routing tables, proxy config, or interface details.

## Rendering Contract

Use a compact, labeled format that is easy to grep in traces. Example shape:

```text
## Dynamic Environment Context
Environment context:
- os: macOS
- arch: arm64
- shell: zsh
- cwd: /Users/example/workspace/project
- git_branch: main
- git_modified_files_count: 3
- process_name: zsh
- session_type: terminal
- tty: true
- timestamp: 2026-06-10T11:35:41+08:00
```

For SSH, the block may include:

```text
- session_type: ssh
- ssh_remote_host: build-host
- local_writes_disabled: true
```

The `timestamp` line must remain last after truncation. If truncation removes fields, it should remove or shorten earlier optional values before moving timestamp away from the tail.

## Implementation Shape

1. Keep helpers private and local to existing request assembly boundaries.

2. Prefer this flow:
   - Collect source facts from existing `AIAgentContext` values and active-session helpers.
   - Build a bounded `LocalEnvironmentContext` or equivalent private struct.
   - Render that struct into the M9.1 `Dynamic Environment Context` layer.

3. A new `AIAgentContext::Environment` variant is acceptable only if implementation proves values must cross controller/request boundaries. If added, it must be treated as a transport snapshot derived from existing sources, not a new source of truth.

4. Reuse existing source APIs:
   - `AIAgentContext::Directory` for cwd.
   - `AIAgentContext::ExecutionEnvironment` for OS and shell.
   - `AIAgentContext::CurrentTime` for timestamp.
   - `AIAgentContext::Git` for branch/head-derived fields, excluding commit SHAs from rendering.
   - `ActiveSession::is_local()` or the M7-equivalent session helper for `session_type`.
   - Existing active-session/process helpers for process name and TTY when available.

5. Avoid duplication:
   - If Directory, ExecutionEnvironment, CurrentTime, or Git facts are represented in the environment block, the old generic context renderer should not also render those same facts as separate sections in the same request.
   - Project rules, file attachments, selected text, images, codebase context, skills, and block attachments remain in their existing context paths.

6. Keep M9.1 layer order unchanged:
   - `Identity`
   - `Capability Advertisement`
   - `Safety Boundaries`
   - `Tool Catalog`
   - `Dynamic Environment Context`
   - `Current Turn`

7. Keep plan-mode and normal-mode prompt wording unchanged outside the environment block.

8. Keep request truncation behavior after message assembly, but enforce the M9.2 block cap before normal message truncation.

## Size Cap

M9.2 has a hard cap of 500 tokens equivalent for the rendered environment block.

Implementation should use a conservative character cap plus field-level truncation because tokenization is provider-specific. The final PR must define the constant and explain the approximation.

Cap rules:

1. Keep labels intact.
2. Prefer omitting optional fields over rendering partial labels.
3. Truncate individual long values such as `cwd`, `git_branch`, `process_name`, and `ssh_remote_host`.
4. Preserve `timestamp` as the final line.
5. Never use the cap as a reason to include denylisted data.

## Acceptance Criteria

1. Normal-mode system prompt includes a populated `Dynamic Environment Context` layer.
2. Plan-mode system prompt includes a populated `Dynamic Environment Context` layer.
3. Approved-plan implementation requests include the same environment block shape.
4. The block includes available allowlisted fields with correct content shape: `os`, `arch`, `shell`, `cwd`, `git_branch`, `git_modified_files_count`, `process_name`, `session_type`, `ssh_remote_host`, `local_writes_disabled`, `tty`, and `timestamp`.
5. The block excludes every denylisted category: env var values, API keys, file contents, full git history/commit SHAs, full process output, home-directory listing, and network configuration.
6. SSH sessions render `session_type: ssh`, `local_writes_disabled: true`, and `ssh_remote_host` when known.
7. Non-SSH terminal sessions render `session_type: terminal` and do not render `ssh_remote_host`.
8. The environment block is capped at 500 token equivalent and truncates safely when values are long.
9. The M9.1 six-layer order remains intact; trace/layer-position checks still find all six layer headings.
10. `timestamp` is ISO 8601 and remains the final rendered environment field.
11. Existing local-agent tests, M9.1 layer tests, plan-mode tests, approved-plan tests, and Finalize request tests continue to pass.
12. Installed Dev trace evidence proves the actual provider request body contains the environment block with sample real values and no committed diagnostics.

## Required Tests

Add or update 8-10 focused tests near the local request assembly and controller context collection:

1. `local_environment_context_renders_allowlisted_fields`
   - Covers OS, arch, shell, cwd, git branch, modified count, process name, session type, TTY, and timestamp shape.

2. `local_environment_context_omits_denylisted_fields`
   - Uses sentinel strings that look like env vars, API keys, commit SHAs, file contents, process listings, home listings, and network config; asserts they do not appear.

3. `local_environment_context_ssh_session_marks_writes_disabled`
   - Non-local session renders `session_type: ssh`, `local_writes_disabled: true`, and remote host when known.

4. `local_environment_context_terminal_session_omits_ssh_host`
   - Local terminal session renders `session_type: terminal` and no `ssh_remote_host`.

5. `local_environment_context_enforces_size_cap`
   - Long cwd/branch/process/host values stay within the configured cap.

6. `local_environment_context_timestamp_is_last`
   - Timestamp is ISO 8601 and the final environment field.

7. `local_system_prompt_keeps_m9_layers_with_environment_context`
   - The six M9.1 layers are still present and ordered with the environment block inside the fifth layer.

8. `local_layered_prompt_static_prefix_excludes_environment_context`
   - Static prefix before `Dynamic Environment Context` does not change when cwd/branch/timestamp changes.

9. `local_plan_mode_includes_environment_context_without_mutating_tools`
   - Plan mode includes the environment block and still advertises only plan-allowed tools.

10. `local_finalize_request_still_omits_tools`
   - Finalize behavior remains `tools=[]` and `tool_choice="none"`.

If implementation keeps existing M9.1 tests with stronger assertions, the exact names can differ, but each behavior above must be covered.

## E2E / Trace Verification

M9.2 is prompt/request assembly work, so source tests are not sufficient.

Implementation PR must use the same five-phase trace pattern as M9.1:

1. Add temporary local request-body instrumentation before install; do not commit diagnostic `eprintln` calls.
2. Emit a marker such as `[M9-2-TRACE]` with the final system prompt and tool count.
3. Install Dev with the trace overlay.
4. Run a simple local-agent normal request and a plan-mode request.
5. Verify the trace contains:
   - the six M9.1 layer headings in order;
   - the populated `Dynamic Environment Context` block;
   - representative values for at least `os`, `arch`, `shell`, `cwd`, `session_type`, and `timestamp`;
   - `timestamp` as the final environment field;
   - `tools_count` consistent with the request mode.
6. Verify the trace does not contain denylisted sentinel values.
7. Remove the trace overlay.
8. Rebuild and reinstall clean Dev.
9. Verify source and installed binary contain no M9 diagnostic strings.

Recommended cleanup checks:

```bash
rg -n "M9-2-TRACE|M9-DIAG|M9-TRACE" app/src/ai/agent/local app/src/ai/blocklist
strings "/Users/yizhang/Applications/Warp Dev.app/Contents/MacOS/warp" | grep -c 'M9-2-TRACE'
codesign --verify --deep --strict "/Users/yizhang/Applications/Warp Dev.app"
```

## Risks

1. **Sensitive data leakage:** avoid by allowlist-only collection and explicit denylist tests.
2. **Cache churn:** avoid by rendering dynamic data only in the fifth M9.1 layer and keeping timestamp last.
3. **Duplicate context:** avoid by folding legacy Directory/ExecutionEnvironment/CurrentTime/Git sections into the environment block for local direct requests.
4. **SSH ambiguity:** avoid by using existing session locality helpers and marking local writes disabled for SSH rather than relying on prompt text for enforcement.
5. **Git scope creep:** avoid by rendering branch and count only, and escalating before adding git commands or commit SHA rendering.
6. **Trace false confidence:** avoid by requiring installed Dev trace evidence plus clean binary verification.

## Escalation Conditions

Escalate before implementation continues if:

1. Any allowlisted field requires a new source of truth or unsafe shell command to collect.
2. `git_modified_files_count` cannot be derived from existing bounded metadata without running git status or enumerating file names.
3. SSH host/process/TTY helpers are unavailable or would require broad process/network inspection.
4. The 500-token cap forces removal of fields that the CTO requires as always-present.
5. Keeping legacy context sections and the new environment block would duplicate or contradict facts in the same provider request.
6. Trace shows dynamic values before the `Dynamic Environment Context` layer.
7. Existing M8/M9 plan, implementation, action-result resume, or Finalize tests regress.

## Rollout

M9.2 ships to Dev only after:

1. This sub-spec PR is approved and merged.
2. Implementation PR passes focused environment-context tests and existing local-agent suites.
3. Installed Dev trace verifies the environment block in actual request bodies.
4. Trace diagnostics are removed from source and from the installed binary.
5. M8.3 and M9.1 e2e remain green.

No Stable promotion is part of M9.2.
